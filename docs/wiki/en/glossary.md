# Glossary

The terms used in the program and in this wiki, explained once.

**Archive (vault)**  
A complete, independent container of records, models and tags. You can have as many as you like and
move between them from the switcher. See [Folders and archives](/en/guide/folders-archives).

**Attachment**  
An image or PDF associated with a record. The file is copied into the working folder, so the record
remains valid even if the original is moved.

**Authority list**  
The list of people and places found in the records; renaming an entry here rewrites the name
everywhere.

**Change control**  
The panel listing changes made locally and not yet sent to the remote archive, with the option of
undoing some of them. See [Change control and history](/en/sync/versions).

**Controlled vocabulary**  
A list of permitted values, shared by several fields and several models. See
[Vocabularies](/en/guide/vocabularies).

**Document model (type)**  
The list of fields that appear in a record. It determines the shape of your archive. See
[Document models](/en/guide/models).

**Fetch**  
The command that asks the remote whether there is anything new, without downloading or sending
anything.

**Folder (sub-archive)**  
An internal subdivision of an archive, as in a file manager. It is for browsing, not for separating:
search runs across every folder of the open archive.

**History (cloud)**  
The list of earlier versions of the archive saved on the remote, which can be consulted and restored.

**Hub**  
The common server on which a shared archive lives. Every participant still keeps their own complete
local copy.

**Link (relation)**  
A reference between two records: it is written on one, and the other shows it as incoming. See
[Links](/en/guide/links).

**Metadata**  
The data describing the document (shelfmark, date, author, writing support…), as distinct from the
transcription, which is the text of the document.

**OCR**  
Automatic recognition of text inside images and PDFs. It runs on your computer. See
[OCR](/en/guide/ocr).

**Personal archive**  
An archive connected to a remote for automatic backup only, with no collaborators.

**Record**  
The description of a single document: metadata, attachments and transcription.

**Record history**  
How a single record changed over time, reconstructed from snapshots. Right-click menu on the record.

**Record-specific field**  
A field that belongs to a single record and not to its model. See
[Record-specific fields](/en/guide/custom-fields).

**Required / unique field**  
*Required* blocks saving if the field is left empty; *unique* does not block, but flags that the
value already exists in another record.

**Saved search**  
A combination of filters stored under a name and recalled with one click.

**Shared archive**  
An archive connected to a remote server on which several people work together.

**Shelfmark**  
The archival identifier of the document. It is the field that drives sorting and retrieval.

**Snapshot**  
A picture of the whole archive, taken automatically and stored on your disk.

**Synchronisation**  
Keeping the archive on your computer aligned with its remote copy. Optional. See
[How it works](/en/sync/how-it-works).

**Table view**  
The rows-and-columns presentation of the list, an alternative to the record grid, with configurable,
sortable columns.

**Tag**  
A free label applied to a record to group it across folders and models.

**Trash**  
Where deleted records go, for 30 days. It is not synchronised: it is yours. See
[Trash, snapshots and history](/en/data/trash-snapshots).

**Working folder (workspace)**  
The folder on your disk where ArchiView saves everything. You choose it on first run and can change it
in the settings. See [Where your data is stored](/en/data/storage).
